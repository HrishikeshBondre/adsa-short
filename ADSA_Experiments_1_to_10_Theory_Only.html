EXP 01

Construct a Binary Search Tree and Perform Preorder, Inorder and Postorder Traversals

A Binary Search Tree (BST) stores smaller values in the left subtree and larger values in the right subtree. Traversals visit each node in a specific order:

  • Inorder: Left → Root → Right; produces values in sorted order.
  • Preorder: Root → Left → Right.
  • Postorder: Left → Right → Root.

Important complexity / note: Time: O(n) for each traversal, where n is the number of nodes.

EXP 02

Implement Insert, Delete, Search and Display Operations on a Binary Search Tree

A BST supports efficient data operations by comparing each value with the current node and moving left or right.

  • Insert: Adds a new value in its correct position.
  • Search: Checks whether a value exists.
  • Delete: Removes a node while preserving the BST property.
  • Display: Inorder traversal displays values in sorted order.

Important complexity / note: Average operation time: O(log n); worst case: O(n) for an unbalanced tree.

EXP 03

Implement Prim’s and Kruskal’s Algorithms

Prim’s and Kruskal’s algorithms find a Minimum Spanning Tree (MST), which connects all vertices of a connected, weighted graph with minimum total edge weight and no cycles.

  • Prim’s algorithm: Starts from one vertex and repeatedly adds the lowest-weight edge connecting the tree to an unvisited vertex.
  • Kruskal’s algorithm: Sorts edges by weight and adds the next lowest edge if it does not create a cycle.

Important complexity / note: Prim’s (adjacency matrix): O(V²). Kruskal’s: O(E log E).

EXP 04

Implement 0-1 Knapsack Using Dynamic Programming

The 0-1 Knapsack problem selects items with given weights and values to maximize total value without exceeding the capacity. Each item can be selected only once or not selected.

  • Dynamic programming stores the best value for each item count and capacity.
  • For each item, compare excluding it with including it when it fits.

Important complexity / note: Time and space: O(nW), where n is the number of items and W is the capacity.

EXP 05

Solve the N-Queens Problem Using Backtracking

The N-Queens problem places N queens on an N × N chessboard so that no two queens attack each other.

  • Place one queen in each row.
  • Check that its column and both diagonals are free.
  • If no safe position is available, backtrack and move the previous queen.

Important complexity / note: Backtracking tests possible placements and abandons invalid arrangements.

EXP 06

Find the Sum of Subsets Using Backtracking

The Sum of Subsets problem finds subsets of a given set whose elements add up to a target value.

  • For each number, explore two choices: include it or exclude it.
  • When the sum equals the target, record the subset.
  • Stop exploring a path when it cannot produce a valid target (for example, when the sum exceeds the target for positive numbers).

Important complexity / note: Worst-case time: O(2ⁿ), because each of n numbers has two choices.

EXP 07

Implement the Floyd–Warshall Algorithm

Floyd–Warshall finds the shortest paths between every pair of vertices in a weighted graph.

  • Start with the graph’s distance matrix.
  • Consider each vertex as an intermediate point and update distance[i][j] if distance[i][k] + distance[k][j] is smaller.

Important complexity / note: Time: O(V³). Space: O(V²).

EXP 08

Implement the Bellman–Ford Algorithm

Bellman–Ford finds shortest distances from one source vertex to all other vertices. It supports negative edge weights.

  • Relax every edge V − 1 times, updating a distance when a shorter path is found.
  • Check all edges once more; if a distance can still decrease, a reachable negative-weight cycle exists.

Important complexity / note: Time: O(VE). Space: O(V).

EXP 09

Implement the Naïve String Matching Algorithm

Naïve string matching searches for a pattern by comparing it with every possible substring of the text having the same length.

  • Shift the pattern one position at a time.
  • Compare characters; record the starting index whenever all pattern characters match.

Important complexity / note: Worst-case time: O(nm), where n is text length and m is pattern length.

EXP 10

Find the Longest Common Subsequence (LCS)

The Longest Common Subsequence is the longest sequence that appears in two strings in the same relative order; characters do not need to be consecutive.

  • Use a dynamic-programming table for prefixes of both strings.
  • If characters match, add 1 to the diagonal value; otherwise take the maximum of the top and left values.

Important complexity / note: Time: O(mn). Space: O(mn), where m and n are the string lengths.
